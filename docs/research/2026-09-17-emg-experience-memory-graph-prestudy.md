## TL;DR

1. **主张**：Agent 纠错不该靠测试时的 LLM 反思循环（脆、贵、不迁移），而应**离线算清楚、测试时一次执行**——把「探索轨迹 vs 专家轨迹」的差做成图编辑路径（确定性 diff），浓缩成自然语言纠错规则存进图记忆，检索注入即用，零重试。
2. **对本仓最有价值的一条**：记忆里存的应是**失败修复规则**（「在条件 X 下做 Y、别做 Z」），而不只是成功事实/工作流——这恰好是现有记忆线（L1 事实抽取、SOP 萃取、触发器召回）都没覆盖的缺口。
3. **落地判断**：概念级移植可行且有独特地基——task-tree 的 **fork 谱系天然提供「同一任务的失败轨迹 + 修复后成功轨迹」配对**（EMG 的硬前提）；本仓工具调用词汇本身高度规范化（tool name + JSON args），同任务配对用**序列编辑距离即可**，不需要论文的 FGW 最优传输。
4. **不引入**：论文代码面向文本游戏（ALFWorld/ScienceWorld）的归一化动作词汇，直接复用价值为零；吸收的是「离线确定性 diff → 纠错规则记忆 → 检索注入」的方法骨架。

## 1. 论文机制拆解

### 1.1 三段管线

```
准备期（离线，每训练任务一次）
  探索轨迹 + 专家轨迹（配对）
    → 有向动作决策图×2（节点=归一化动作(type,object,receptacle)，边=前置观察）
    → FGW 最优传输对齐（Fused Gromov-Wasserstein，离散化为硬匹配）
    → 提取：公共子图（正确工作流） + 图编辑路径（插入/删除/改标 = 具体纠错指令）
    → LLM 仅负责把编辑路径措辞成自然语言「任务内洞察」（存为图节点）

跨任务期（离线）
  语义近邻任务（top-k 嵌入）的专家图两两匹配 → 共享子图 = 「跨任务洞察」（存为图边）

测试期（一次执行）
  嵌入查询 → top-K 节点洞察 + 近邻的 top-T 边洞察 → 注入 prompt
  —— 无反思、无重试、无循环
```

两个图构造技巧：**节点复用**（重复相同动作共享节点、挂多条前置观察）与**连续无效动作并行化**（"nothing happens" 类失败尝试挂在同一有效状态节点上）——后者正是「失败簇」的结构化表达。

### 1.2 结果与消融（要点）

- ALFWorld 未见任务 SR：Qwen3-4B **60.45%** vs 最强反思基线 42.54%（4B+EMG ≈ 大模型+常规基线）；ScienceWorld 未见（DeepSeek-V4-Flash）同样领先。
- 消融：**节点洞察（任务内规则）是主驱动**（ALFWorld 未见 21.64%→52.99%）；边洞察（跨任务模式）对小模型/难任务增益最大（9.48%→16.11%）。
- 优雅退化：即使匹配全错，编辑路径仍合法——退化为「照专家轨迹走」，不会产生有害规则（附录 C）。
- 成本：离线图匹配 ~0.49s/对（CPU）；测试时单次执行远快于 5 轮反思基线。

### 1.3 局限（论文自认）

- **依赖配对专家轨迹**（ALFWorld 3321 任务仅 1275 有）；自生成成功轨迹是 future work——本仓的 fork 谱系恰好是这个 future work 的现成答案。
- FGW 匹配 ~90% 召回（但编辑路径仍有效）。
- 仅在文本游戏环境评测；大模型+复杂推理域增益有天花板。

## 2. 与本仓记忆线对位

| EMG 概念 | 本仓对应物 | 现状差距 |
| --- | --- | --- |
| 失败修复规则（「X 下做 Y 别做 Z」） | **无直接对应**——L1 抽事实、SOP 萃流程、tmem 补触发召回，都不是「纠错规则」 | **缺口即机会**（本预研核心） |
| 配对轨迹（探索 vs 专家） | **task-tree fork 谱系**：失败分支 + 修复成功的子分支 = 同任务配对；另有 session replay 兜底 | 数据已在，从未按此用途挖掘 |
| 确定性 diff（编辑路径）替代 LLM 反思 | memory-audit 的 proposal 合成靠 LLM； cmb 线有「崩溃合成收尾」但非轨迹 diff | 机械门优先哲学同向，机制可补 |
| 图结构记忆（节点=任务内 / 边=跨任务） | L0–L3 分层 + RRF 混合召回 + 嵌入服务 | 分层维度不同（时效 vs 任务粒度），可叠加 |
| 测试时注入（top-K 节点 + top-T 边） | boot context（行为画像，默认关）+ 记忆注入通道 | 注入面已有 |
| 失败簇结构化（连续无效动作并行化） | cmb CodeBrain 失败模式分类学（CMB-6 台账） | 分类学有了，「可检索的失败记忆」没有 |

**结论**：EMG 不是替换任何现有记忆机制，而是补上「**失败→修复**」这一象限：现有线都在「成功经验」侧（事实/流程/触发），EMG 验证了「失败修复规则」作为可检索记忆的单独价值（消融里主驱动）。

## 3. 落地建议（提案，需另立 spec）

**P1 · 修复规则记忆（repair-rule memory）**——记忆线候选：

1. **数据源**：task-tree 谱系里筛「父分支失败 + 子分支同任务成功」的 fork 对（谱系馈赠机制已有 lineage 数据）。
2. **确定性 diff**：两分支的工具调用序列做编辑对齐（LCS/编辑距离即可——同一 harness、同一工具词汇，`{tool, 关键 args 摘要}` 为对齐单元）；产出「删除的动作簇 / 替换 / 插入」= 编辑路径。**LLM 只做措辞**（编辑路径 → 双语规则句），与 memory-audit 的「确定性证据扫描→LLM proposal」三段式完全同构。
3. **存储**：规则挂 L1/L2（带 `kind: repair-rule` 与失败上下文触发词）；跨任务模式经现有嵌入近邻聚合（边洞察的等价物）。
4. **注入**：stuck 检测/轮次卡顿时检索注入（cmb-next backlog 的 premature-stop/stuck 检测是天然触发点）；boot context 默认关的先例照搬——规则注入也应显式可关。
5. **红线**：本地计数/隐私纪律照旧；规则的「优雅退化」对齐——diff 无信号时**不产规则**（宁缺勿滥，EMG 退化语义的安全侧）。

**不做**：FGW/最优传输（同任务 fork 用不上）；文本游戏动作归一化；把 EMG 的「测试时零循环」绝对化——本仓的自动恢复/反思机制服务别的场景，不冲突。
