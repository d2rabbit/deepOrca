# DeepOrca UI/UX 重设计愿景 v2：Orca Deck · 无框指挥舱

> 日期：2026-08-19（v2，按反馈修订） · 前置阅读：[[2026-08-19-ui-ux-audit-report]]（现状审计）
> 设计稿：[[2026-08-19-ui-ux-redesign-wireframes]] · 视觉稿：`2026-08-19-ui-ux-redesign-mockup.html`
>
> **v2 修订说明**：v1 的「五区 rail + 二级面板 + 右栏 Inspector」评审反馈是"VS Code 影子太重"——确实，那是 activity-bar 心智换了皮。v2 换骨：**移除全部常驻侧栏**，导航从"收纳进栏"改为"召唤式（Summon, don't dock）"，布局从 IDE 网格改为无框工作台。阶段化的核心主张保留并强化。

---

## 1. 竞品格局：所有 coding agent 都长成了同一个样子

| 产品 | 交互范式 | 一句话本质 |
|---|---|---|
| **Cursor / Windsurf / Trae** | IDE 优先 | 编辑器是中心，agent 是侧栏里的聊天 |
| **VS Code Copilot** | IDE 附属 | chat 是 activity bar 里的又一个图标 |
| **Codex 桌面版** | 任务队列 | 一盘异步任务卡片，点进去看 diff 和日志 |
| **ChatGPT / Claude / Threads 系** | 平铺线程 | 一维消息流，从顶滚到底 |
| **Claude Code / Gemini CLI** | 终端 | 文本气泡换成 ANSI 字符 |

以及要诚实承认的：**DeepOrca 现状和 v1 方案都属于第一类**——rail + 侧栏 + 主区 + 右栏的网格，是 VS Code 给所有开发者工具烙下的思想钢印。

这些产品共同的交互缺陷：

1. **消息流是平的**——agent 干了 20 分钟活之后，"它现在进行到哪一步"无法回答，只能往回滚。
2. **上下文是黑盒**——token 还剩多少、什么时候被压缩、丢了什么，用户一概不知。
3. **控制是打断式的**——权限请求把流掐断，用户在"盯着等"和"回来发现卡在第一个问题"之间二选一。
4. **导航是地契式的**——功能被固定在屏幕的某块地产上（侧栏、面板、tab），屏幕 30% 的面积长期支付给"现在用不到的东西"。

## 2. v2 设计转向：从「收纳」到「召唤」

> **Summon, don't dock.** 功能不占有屏幕，只在被召唤的瞬间出现，用完即走。

v2 删掉的：rail、二级面板、常驻 Inspector 右栏、状态栏、面板 tab——**所有 VS Code 式地契**。
v2 得到的：一块完整的、无边框的工作台面。内容列是唯一常驻物。

空出来的导航需求由三个召唤层承接：

| 召唤层 | 入口 | 承接什么 |
|---|---|---|
| **命令层** ⌘K | 全屏居中浮层 | 一切动词：切会话、开面板视图、换主题、slash 命令、动作 |
| **任务总台** ⌘⇧M | 全屏卡片墙 | 一切名词：所有会话/任务作为活卡片，一眼总览，点击进入 |
| **边缘抽屉** | 屏幕左/右缘悬停或快捷键滑入 | 快速一瞥：文件树、git 状态、进程输出——**瞬时覆盖，失焦即收**；需要常驻时可手动"钉住"为浮动窗 |

Inspector 的"跟随焦点"主张保留，但从停靠栏改为**焦点卡（Focus Card）**——一块锚定在选中对象旁、可拖动、可钉住的浮动卡片，像 macOS 的 Quick Look，而不是 VS Code 的侧栏。

## 3. 核心概念：阶段带（Stage Ribbon）

阶段化主张从 v1 的"消息列左侧竖脊柱"升级为**置顶水平阶段带**——它同时取代现状的 TopBar 与状态栏，成为整个窗口唯一的常驻结构件（40px）：

```
◉ 重构权限为审批队列    理解 ●━━ 计划 ●━━ 执行 ◉╌╌ 验证 ○╌╌ 交付 ○    62% ctx  🔔  ⚭
                       已完成───────  进行中 ↑呼吸脉冲   未开始
```

- **它回答竞品回答不了的问题**："进行到哪一步、之前做了什么、各花了多少"——不看消息流，一瞥即得。
- 每个阶段节点可点击 → 消息流滚动定位到该阶段锚点；hover → 起止时间、token、工具调用数。
- 消息流内部按阶段分组，每组可整段折叠成一行摘要（"执行：改了 7 个文件 · 3 条命令 · +412/−87"），长任务从 3000 行滚屏压回一屏。
- 阶段归段走启发式（首个读类工具→理解、批准 plan→计划、首个 write/bash→执行、首个 test/build→验证、idle 且有产出→交付），不消耗模型。
- 空闲时阶段带退化为纯会话标识；任务一启动，它才"亮"起来——** chrome 随工作出现，随完成隐去**。

这是与 Cursor（编辑器中心）、Codex（任务队列）、Threads（平铺线程）都不同的空间模型：**时间是主轴，空间是召唤的**。

## 4. 六条设计主张（v2）

### 4.1 零常驻侧栏（Zero Chrome）
内容列（max 760px 居中）占据窗口的绝对主体。没有 rail、没有侧栏、没有状态栏。屏幕不再为"可能用到"付费。专注模式 ⌘. 连阶段带也隐去，只剩内容与输入。

### 4.2 命令层为枢纽
⌘K 升级为真正的中枢：fzf 风格模糊评分，覆盖所有会话、视图、主题、slash 命令、设置项、动作——快捷键表、slash 菜单、命令面板三份清单合并为同一注册表的三个视图。新用户 90% 的"这功能在哪"都由 ⌘K 回答。

### 4.3 任务总台（Mission Control）
⌘⇧M 唤出全屏卡片墙：每个会话是一张活卡片（当前阶段缩略带、最新一行输出、token 计、等待审批红点）。这是多会话的"总览→钻取"心智，取代会话列表侧栏，也天然成为 onboarding 的第一印象。

### 4.4 焦点卡（Focus Card）
选中即检视：点消息里的文件/权限项/token 计/设计产物 → 一张 380px 浮动卡片锚定在旁（diff、风险明细、用量拆解、预览）。可拖动、可钉住（钉住后成为持久浮动窗，多个可并存）、Esc 即关。主区永远不被整页替换——设置同样是浮层。

### 4.5 控制不打断
权限请求聚合为**审批队列卡**（一轮所有待决项一张卡，风险三色，高危强制逐项），agent 继续执行无风险步骤，用户离开不阻塞；deny 决定以可见胶囊呈现。此主张 v1 评审无异议，原样保留。

### 4.6 浮层归栈
所有浮层（命令层、总台、焦点卡、抽屉、设置、undo、diff）进统一栈：Esc 关最上层，⌘⇧Esc 全关。因为 v2 一切皆浮层，这条从"整洁性要求"升格为**架构支柱**。

## 5. 人体工程学基线

- **视线动线**：内容列居中、max 760px（约 75 字符/行），阶段带在正上方——阅读视线从顶到底一条直线，零左右扫视（VS Code 布局的三栏扫视被消除）。
- **Fitts 定律**：命令台悬浮底部居中，发送键 44×44 固定右下；停止/重试/审批都在输入区一臂之内。
- **键盘全覆盖**：⌘K 命令层、⌘⇧M 总台、⌘E 文件抽屉、⌘I 钉住焦点卡、J/K 阶段跳转、Esc 退栈、⌘. 专注模式。移除 ⌘O/⌘J 冗余绑定。
- **密度与字号**：三档密度 + 界面字号独立缩放；正文基准 14px、行高 1.6；辅助文字不低于 11.5px；全主题过 WCAG AA。
- **动效纪律**：`prefers-reduced-motion` 全局生效；阶段带只呼吸、不位移；抽屉/浮层滑入 ≤200ms。
- **一致性**：emoji 图标清零（全部描边 SVG）；tooltip 统一 data-tip 体系；i18n 硬编码清零。

## 6. 视觉方向：无框 + 声呐

以 orca 深色为旗舰主题，v2 的无框布局让"深海"隐喻终于成立：

- 窗口即深海：底色近黑，内容列是唯一被"照亮"的水域。
- 阶段带的当前阶段是**声呐脉冲**——全界面唯一的自发光动元素，视线自然归位。
- 浮层用玻璃拟态（backdrop blur + 1px 光边），与平面的工作区形成明确的"图层上下"关系。
- 6 套主题架构原样保留；新组件只消费 `--ui-*` token，禁止硬编码色值。

## 7. 落地路径

| 阶段 | 内容 | 对应审计项 |
|---|---|---|
| **第一波：止损**（与布局无关，v1 评审已认可） | 修复右栏 grid 归属或干脆移除死代码；rail 取消条件显隐；emoji→SVG；统一 Esc 栈 | P0-1/2、P2-1/2/3 |
| **第二波：无框化** | 拆 rail/侧栏/右栏 → 阶段带 + 命令层 + 边缘抽屉 + 焦点卡；设置浮层化；OverlayStack 落地 | P1-1/2/3/4 |
| **第三波：差异化** | 任务总台卡片墙；阶段折叠摘要；审批队列；任务树画布（浮层化）；通知中心；onboarding | P1-5、愿景 §3–4 |

第二波是脱胎换骨的一步：renderer 的 view 状态从 `sidebarView × mainView` 复合状态机简化为 **「内容列 + 一个浮层栈」** 两个概念——这同时消灭了审计中"状态组合空格"的 bug 温床（P1-2）。
