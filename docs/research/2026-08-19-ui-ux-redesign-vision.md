# DeepOrca UI/UX 重设计愿景 v3：Orca Deck · 工单工作台

> 日期：2026-08-19（v3，按第二轮反馈修订） · 前置阅读：[[2026-08-19-ui-ux-audit-report]]
> 设计稿：[[2026-08-19-ui-ux-redesign-wireframes]] · 视觉稿：`2026-08-19-ui-ux-redesign-mockup.html`
>
> **版本演进**：v1「阶段指挥舱」= VS Code 式五区 rail（被否：VS Code 影子）→ v2「无框指挥舱」= 召唤式浮层导航（被否：只动了 chrome）→ **v3「工单工作台」= 换本体**。
>
> **v3 修订说明**：v2 的反馈一针见血——把侧栏换成浮层，中心还是那个聊天框；交互逻辑还是"你发一句 → AI 做一段 → 弹卡问你 → 你再发一句"的回合制。气泡、头像、"思考中…"、流式打字机、审批弹卡，这些不是装饰问题，是**对话本体论**的症状。v3 把对话从界面的王座上拉下来：**消息流降级为飞行记录仪，工单（Work Order）升格为界面本体。**

---

## 1. 诊断：什么是"AI 感"，为什么所有产品都有

"AI 感"不是配色或圆角，是三个深层约定：

1. **对话即界面**——屏幕的主体是消息流，工作是对话的副产品。
2. **回合制**——你说 → 它做 → 它问 → 你答。时间被切成一问一答的薄片，用户被训练成"应答器"。
3. **拟人化包装**——头像、气泡、"思考中…"、打字机光标，把工具伪装成同事。

Cursor、Codex、ChatGPT、Claude Code 全部共享这三条——区别只在气泡外面套的是编辑器、任务队列还是终端。v1/v2 的 DeepOrca 方案也一样：脊柱和阶段带只是在消息流旁边加仪表，**仪表再漂亮，人还在陪聊**。

v3 的破法是对着三条约定逐条造反：

| 约定 | v3 的反面 |
|---|---|
| 对话即界面 | **工件即界面**：屏幕主体是正在被建造的东西（工单/步骤/diff），对话是它的脚注 |
| 回合制 | **并行值守**：agent 持续工作，用户在任意对象上随时介入，无需等它问、无需等它停 |
| 拟人化 | **仪器化**：状态用仪表呈现（数字、量表、状态灯），不用表情和气泡 |

## 2. 核心概念：工单即界面（The Work Order is the Interface）

用户给的不是"消息"，是**目标（Goal）**。agent 接到目标后产出**工单**——一份活的、可操作的执行文书。界面主体就是这份工单：

```
目标：把权限改成批量审批                          约束: 高危逐项 ✓ 不碰 session.ts
┌─ 工单 #3 ───── 7 步 · 跑了 42s · $0.04 · ●进行中 ──────────┐
│                                                              │
│  [① 读取权限模块 ✓] [② 设计队列结构 ✓] [③ 改核心 ◉] [④ 验证 ○]│  ← 步骤板
│                                                              │
│  ◉ ③ 改 core/permissions.ts                    gate: 自动 ▾  │
│      +45 −12 · diff ▸ · 日志 ▸ · 💬2 · ⚠1 待决               │
│  ○ ④ typecheck + test                          gate: 完成确认 │
└──────────────────────────────────────────────────────────────┘
自律度  ━━━●── 关键步骤确认        ⏸ 刹车
```

**步骤是可操作对象，不是聊天记录**：拖拽重排、划线删除、点开改范围（chips 形式增删文件）、逐步设置闸门（自动 / 完成时确认 / 执行前确认）。agent 按工单施工，你对工单做任何修改，它立刻按新工单继续——**你改的不是对话，是正在进行的工作本身**。

## 3. 五个第一性对象

| 对象 | 定义 | 对应现状（引擎原语，见 §6） |
|---|---|---|
| **Goal 目标** | 工作的第一身份，取代"会话"作为顶层概念 | session + 首条 prompt |
| **Work Order 工单** | 目标的活执行文书：步骤、约束、闸门、成本 | UpdatePlan + 会话状态 |
| **Step 步骤** | 可重排/删除/改范围/设闸门的对象，带状态灯 | plan 条目 + 工具调用序列 |
| **Intervention 介入** | 挂在任意对象上的用户批注（目标/步骤/文件/hunk），agent 读作转向指令 | 用户消息（但带对象锚点） |
| **Tape 记录仪** | 完整消息流/事件流，只读，⌘T 打开 | 现有 MessageList 原样搬迁 |

**介入机制是 v3 的交互核心**：底部不再是"对 AI 说话"的输入框，而是**指示条**——它永远标注着"对 [当前选中对象] 说"：

```
对 [③ 改 permissions.ts]：这个文件的高危降级逻辑再保守一点        ⌘↵
```

未选中任何对象时，指示条默认指向目标本身。对话没有消失，但它从"时间轴上的一串气泡"变成"工件上的批注"——像 Figma 的评论、像 code review 的 inline comment，而不是微信。

## 4. 交互逻辑：从回合制到并行值守

**回合制的消亡**。v3 里没有"等你回复才能继续"：

- **闸门前置，审批消失**：不再在工作中途弹卡打断。你在工单下发前（或任意时刻）给步骤设闸门：全自动 / 完成时确认 / 执行前确认。高危操作（红）默认"执行前确认"，不可被全局放开——安全底线不变，但表达方式从"打断"变为"交通规则"。
- **自律度旋钮**：一个物理感的三档控件（全自动 / 关键确认 / 每步确认），是工单级的默认值，步骤可局部覆盖。它取代现状的逐 scope 权限向导——权限从"审问"变成"授权档位"。
- **刹车 ⏸**：大而永远可用的物理按钮。拍下即冻结，工单停在当前步骤，所有上下文原地保留。
- **agent 的提问挂在步骤上**：它卡在 ③ 需要决策时，问题以内联选项出现在 ③ 卡片上，同时 ④⑤ 不受阻的准备工作继续。红点进 🔔，你半小时后回来一次答完——它按答完的新状态继续，而不是干等。

用户的角色从"陪聊 + 应答器"变成"**值守员**"：平时看仪表（阶段带、成本、状态灯），需要时介入具体对象，紧急时拍刹车。

## 5. 去 AI 感清单（视觉与措辞的清洗）

| 清洗对象 | 替换为 |
|---|---|
| 聊天气泡、左右分边 | 表格化的事件行 / 卡片，无气泡无边距游戏 |
| AI/用户头像 | 无头像。来源用字体排印区分（等宽=机器，常规=人） |
| "思考中…" + 三点动画 | 状态灯 + 具体仪表："③ 执行中 · 42s · ↓1.2k tok · 3/7 文件" |
| 流式打字机光标 | 主视图不显示逐字流；原始流在 Tape（⌘T）里 |
| 审批弹卡 | 步骤闸门 + 自律度旋钮 + 内联决策项 |
| "AI 助手""我可以帮你" | 工单文书语气：状态、数量、下一步 |
| 紫色渐变、闪光 ✨ 拟 AI 装饰 | 仪器配色：声呐青只做状态指示，零装饰性发光 |

保留 v2 的空间成果：无框布局、阶段带（现在显示工单进度）、召唤层（⌘K / ⌘⇧M / 抽屉）、焦点卡、浮层栈——它们与工单本体正交，继续成立。

## 6. 可行性：这是一次渲染层革命，不是引擎重写

v3 的五个对象都能映射到现有引擎原语，核心工作量在 renderer：

- Goal/工单/步骤 ← `session` + `UpdatePlan`（计划系统已有，把它从"聊天里的卡片"升格为持久的一等状态）。
- 闸门/自律度 ← `computeToolCallPermissions()` 的策略输入从"逐次问答"改为"读工单闸门表"——`permissions.ts` 的策略面重构，不动执行面。
- 介入 ← 用户消息加 `anchor` 字段（goal/step/file/hunk），prompt 组装时按锚点归位。
- Tape ← `MessageList` 组件原样成为 ⌘T 视图，零重写。
- agent 提问挂步骤 ← `AskUserQuestion` 结果关联当前 step id。

风险诚实说：阶段归段、步骤与工具流的实时对齐是启发式的，会有对不齐的时刻——设计上用"未归类事件"缓冲区兜底，对齐失败时降级显示 Tape 原始流，永不丢信息。

## 7. 落地路径

| 波次 | 内容 |
|---|---|
| **一：止损**（与范式无关，照旧先做） | 右栏死代码、rail 条件显隐、emoji 图标、Esc 栈 |
| **二：工单化** | 工单/步骤数据层（plan 升格为一等状态）→ 工作台主视图 → 闸门+自律度（权限策略面重构）→ 指示条+介入锚点 |
| **三：空间化**（v2 成果并入） | 阶段带接工单进度、⌘K/⌘⇧M/抽屉、焦点卡、Tape=⌘T |
| **四：体验封顶** | 刹车、步骤拖拽编辑、多工单车间墙、onboarding、密度档位 |

第一波之后每一步都可独立发布：工单视图可以先作为可选布局与聊天视图并存（用户可切回 Tape 为主视图），验证后再定为默认。
