## 1. Rail：五区导航

```
┌────┐
│ 🜲  │  ← 产品标识（非按钮，点击=关于）
├────┤
│ ▤  │  ⌘1 工作 Work      ─┐
│ ⎇  │  ⌘2 变更 Changes    │ 当前区按钮左侧
│ ▣  │  ⌘3 资产 Assets     ├ 有 3px 声呐色指示条
│ ◈  │  ⌘4 知识 Knowledge  │
│ ⚙  │  ⌘5 系统 System    ─┘
├────┤  ← 弹性间隔
│ 🔔 │  通知中心（未读红点，常驻不跳动）
│ ⚭  │  设置（浮层，⌘,）
└────┘
```

**规格**

- 全部使用描边 SVG（line 主题图标体系），**emoji 清零**（现状 `App.tsx:1236/1244`）。
- 按钮**永不条件显隐**：tasks 无计划时置灰 + tooltip "当前会话暂无计划"（修 P0-2）。
- 每个区按钮的 tooltip 显示：`名称 ⌘N + 区内 tab 预览`（如 工作：会话 · 任务 · 任务树）。
- 窗口高度不足时 rail 自身可滚动（现状会被裁剪）。

## 2. 二级面板：区内 tab

以 ⌘2 变更区为例：

```
┌─────────────────────┐
│ 变更          ▾ ⌘2  │
│ [Git] [审查] [历史]  │  ← 区内 tab，⌘⇧1/2/3 直达
├─────────────────────┤
│ ● 3 changed files   │
│  M src/App.tsx      │
│  M src/session.ts   │
│  ? docs/new.md      │
│  ─────────────      │
│  ⌘ 提交…            │
└─────────────────────┘
```

- 区切换保留各面板内部状态（滚动位置、展开项）。
- 面板内容点击文件/对象 → **Inspector 跟随显示**，主区不被替换（修 P1-2/P1-3）。

## 3. 消息流 × 阶段脊柱（核心差异化）

```
│ ●───── 理解 · 已折叠 ──────────────── 读了 12 个文件 · 4.2k tok │
│ │
│ ●───── 计划 ────────────────────────────────────────────────── │
│ │   ┌ Plan Card ────────────────────────────┐                  │
│ │   │ 1. 重构权限卡为队列 …        [实施][保持]│                  │
│ │   └───────────────────────────────────────┘                  │
│ │
│ ◉───── 执行 · 进行中 ─────────────── 3/7 文件 · ↓1.2k tok · 42s │
│ ║   ╭ User ─────────────────────────────╮                      │
│ ║   │ 把权限改成批量审批                  │                      │
│ ║   ╰────────────────────────────────────╯                     │
│ ║   ▸ 🔧 edit packages/.../permissions.ts   +45 −12            │
│ ║   ▸ 🔧 bash npm run typecheck           ✓ exit 0             │
│ ║   ┌ 审批队列 · 3 项待决 ────────────────────────┐               │
│ ║   │ 🟡 写 packages/core/src/session.ts   [允许] │               │
│ ║   │ 🟢 读 docs/architecture.md           [允许] │               │
│ ║   │ 🔴 执行 git push                [允许][拒绝] │               │
│ ║   │ [全部允许本轮]            [逐项 ▸ Inspector]│               │
│ ║   └───────────────────────────────────────────┘               │
│ │
│ ○───── 验证                                             （未开始）│
│ ○───── 交付                                             （未开始）│
```

**Stage Spine 规格**

- 宽度 24px，位于内容列左缘；节点 8px 圆点，连接线 2px。
- 状态：未开始（空心灰）/ 进行中（实心 + 1.6s 呼吸脉冲，`prefers-reduced-motion` 时改为静态高亮）/ 完成（实心声呐色）/ 已折叠（节点下挂摘要行）。
- 点击节点 = 折叠/展开该阶段全部消息；`J` / `K` 在阶段间跳转；hover 节点显示阶段 tooltip（起止时间、token、工具调用数）。
- 折叠摘要由结构化数据生成（不消耗 LLM）："改了 N 文件 · 跑了 M 命令 · +a/−b 行 · Xs"。
- 阶段归段规则（启发式，无需模型配合）：首个 read/搜索类工具 → 理解；产出/批准 plan → 计划；首个 write/edit/bash → 执行；首个 test/build/lint 成功调用 → 验证；会话 idle 且存在产出 → 交付。

**审批队列规格**（替代逐条打断，修 P1-5）

- 一个回合的所有权限请求聚合为一卡；每项 = 风险色点 + 一句话 + [允许]。
- 危险项（红）不可被"全部允许本轮"覆盖，必须逐项确认——安全底线。
- 用户离开不打断：agent 继续执行不依赖待决项的工具；待决项静默等待，红点进通知中心。
- 逐项点击 → Inspector 展开该请求的完整命令/差异预览。

## 4. Command Deck（composer 重构）

```
┌────────────────────────────────────────────────────────────────┐
│ ┌─模式─┐ ┌─上下文─┐                                            │
│ │ 对话 ▾│ │ @3文件 │  ┌──────────────────────────────────────┐ │
│ └──────┘ └───────┘  │                                      │ │
│  ┌────┐             │  输入…（/ 命令 · @ 文件 · 拖图）         │ │
│  │附件│             │                                      │ │
│  └────┘             └──────────────────────────────────────┘ │
│  ⬡ Plan     62% ctx ▓▓▓▓░░      flash 改写 ✨    ▶ 发送 ⌘↵    │
└────────────────────────────────────────────────────────────────┘
```

- 模式 chips（对话/计划/自动）取代 Shift+Tab 隐式切换；Plan 态整卡换色保留。
- 上下文仪表从独立组件收编为发送键旁的迷你环（hover 展开现状的 ContextProgress 详情）。
- 发送键 44×44 固定右下角（Fitts）；生成中变为 ■ 停止（原 Esc 仍可用，双通道）。
- 待决审批存在时 composer **不再整体禁用**（修 P1-5 的打断性），仅 placeholder 提示"有 3 项审批待决"。

## 5. Inspector（接通断头右栏，修 P0-1）

```
┌─ Inspector ──────────────── ⌘I ✕ ─┐
│ ▸ permissions.ts 的变更            │
│ ┌────────────────────────────────┐ │
│ │ @@ -106,7 +106,7 @@            │ │
│ │ -  const risk = "high"         │ │
│ │ +  const risk = "medium"       │ │
│ └────────────────────────────────┘ │
│ [在编辑器打开] [还原此文件]          │
└────────────────────────────────────┘
```

内容跟随焦点：文件卡 → diff；权限项 → 命令全文与风险说明；token 计 → 用量拆解；设计产物 → 预览。技术上即把 `.ui-preview-panel` 归入 `.ui-shell` 第 4 轨并启用死代码 `.ui-shell.right-open` / `.ui-rightpanel`（`ui.css:191-212`），面板互斥由 view router 统一管理。

## 7. 任务树：升级为画布视图（差异化 #2）

侧栏列表保留，主区 tab 视图（现状只能从会话徽章进入，P1-3）改为 ⌘1 区内 tab 直达的 **git-graph 画布**：

```
●─●─●─────●  main-line   当前
    \      
     ●─●─●  try/queue-permission   ✓ 已合并回主线
          \
           ●  try/auto-approve     ✕ 已放弃 · 原因：风险过高
```

节点 = 一次任务快照；边 = 分支关系；hover 显示 why 备注；点击切快照（复用现有 task-tree 快照切换能力）。横向平移缩放，迷你地图右下角。

## 8. 通知中心

顶栏 🔔 常驻，聚合：toast 历史、审批待决数、进程异常、任务完成。Toast 本身保留（3.5s），但所有 toast 落档进通知中心——错过不再等于丢失。

## 10. 浮层栈规格（修 P2-3）

全局单一栈 `OverlayStack`：push/push 模态、Esc 弹栈顶、⌘⇧Esc 清空、背景点击仅弹栈顶且仅当非模态。层级：`z-index` 由栈序自动分配，组件不再自管。迁移顺序：CommandPalette → SettingsPanel → UndoModal → ShortcutsModal → DiffOverlay → WorkspaceTrustDialog → 分支冲突 Modal → PrototypeWindow（独立窗口除外）。

## 11. 设计 Token 增补

现有 `--ui-*` 语义 token 架构不动，增补：

```
--ui-sonar:        声呐强调色（各主题定义；orca = #4DE3C2）
--ui-spine-idle / --ui-spine-active / --ui-spine-done
--ui-risk-low / -mid / -high   （沿用权限三色，推广到全局）
--ui-density-space:  density 档位系数（0.875 / 1 / 1.125）
--ui-font-base:      14px（密度系数可缩放）
--ui-motion-pulse:   1.6s（reduced-motion 时置 0）
```

新组件一律消费 token；审计中的 emoji、硬编码色、硬编码字号（13.5px）随迁移清零。
