# 原型设计模块 — 约束与问题记录（Issues）

> 日期：2026-08-31 · 状态：需求记录（未排期）
>
> 背景：为"原型需求 / 原型设计"独立模块划定的行为边界。核心原则：原型设计是
> **工作区内的伴随能力**，不是主对话工作区的占用者。

## Issue 1 — 原型需求与模块设计追随工作区，行为以悬浮对话框承载

原型需求与模块设计跟随当前工作区（workspace）；具体操作行为以**悬浮对话框**
的形式在工作区内进行，不另开独立的全屏/独占界面。

## Issue 2 — 独立原型设计模块不得占用主对话工作区

原型设计模块作为独立模块运行时：
- 不允许占据/遮挡主对话工作区；
- **不产生主工作区的对话记录**——其行为记录走 Issue 3 的任务记录通道，与主会话历史隔离。

## Issue 3 — 所有 agent 操作必须落地任务记录（复用既有 task / 历史模块）

覆盖全部 agent 操作模块：索引与知识（index & knowledge）、代码审查（code review）、
原型设计（prototype design）。操作记录统一落到**已存在的 task 与历史记录模块**
（`specs/task-tree/` 任务树 + 会话历史），不新建第二套记录系统。

## Issue 4 — 主对话区左侧侧栏的展示分工：design 面板 vs 需求文档

主对话区对原型设计与需求模块的行为保持现状——左侧侧栏展示，但需区分两类内容：

| 内容 | 侧栏呈现 |
| --- | --- |
| 原型 / UI 设计 | 专用 **design 面板**（仅原型与 UI 使用） |
| 需求文档 | 普通 **markdown 渲染侧栏** |

同时为侧栏**增加滚动能力**（当前内容超出可视区无法滚动浏览）。
