## 1. 竞品格局：所有 coding agent 都长成了同一个样子

| 产品 | 交互范式 | 一句话本质 |
|---|---|---|
| **Cursor / Windsurf** | IDE 优先 | 编辑器是中心，agent 是侧栏里的聊天 |
| **Codex 桌面版** | 任务队列 | 一盘异步任务卡片，点进去看 diff 和日志 |
| **ChatGPT / Claude / Threads 系** | 平铺线程 | 一维消息流，从顶滚到底 |
| **Claude Code / Gemini CLI** | 终端 | 文本气泡换成 ANSI 字符 |
| **Zed / Trae 等** | IDE + 聊天 | 同 Cursor，换皮 |

四类产品，实质只有两种隐喻：**「编辑器旁边挂个聊天」**或**「聊天里嵌点工具结果」**。共同的交互缺陷也一致：

1. **消息流是平的**——agent 干了 20 分钟活之后，"它现在进行到哪一步"无法回答，只能往回滚。
2. **上下文是黑盒**——token 还剩多少、上下文什么时候被压缩、压缩丢了什么，用户一概不知。
3. **控制是打断式的**——权限请求、提问弹窗把流掐断，用户被迫在"盯着等"和"回来一看卡在第一个问题"之间二选一。
4. **界面是静态的**——工作区、git、终端、预览是互相不知道对方存在的孤岛面板。

DeepOrca 的现有资产——上下文仪表条、任务树（git 式分支）、A2UI 富结果、6 套 token 化主题——恰好是回答这四个缺陷的弹药。缺的是一个把它们组织起来的交互概念。

## 2. 核心概念：从「聊天线程」到「阶段指挥舱」

> **Orca Deck**——聊天不是产品，**任务的进行**才是产品。聊天只是任务的一个视图。

核心动作是把一维消息流折叠成一条**有结构的工作脊柱**：

```
理解 Understand → 计划 Plan → 执行 Act → 验证 Verify → 交付 Deliver
```

agent 的每一轮工作都落在五个阶段之一（由工具调用与计划事件自动归段，无需模型配合），消息流左侧常驻一条细长的**阶段脊柱（Stage Spine）**：

- 它回答竞品回答不了的问题：**「现在进行到哪一步、之前做了什么、花了多少代价」**——不用滚动，一瞥即得。
- 每个阶段可整段折叠成一行摘要（"执行：改了 7 个文件 · 运行了 3 条命令 · +412/−87 行"），长任务的消息流从 3000 行滚屏压回一屏。
- 脊柱即进度条：流式输出时当前阶段呼吸发光；任务完成时整条脊柱亮起收尾动画。

这是与 Cursor（编辑器中心）、Codex（任务队列）、Threads（平铺线程）都不同的第三种空间模型：**脊柱中心，内容为翼**。

## 3. 五大设计主张

### 3.1 导航瘦身：19 → 5

rail 从 19 个平级按钮收编为 **5 个区（Zone）**，每区内部用二级 tab 收纳现有 11 个面板：

| 区 | 快捷键 | 收纳 | 心智 |
|---|---|---|---|
| **工作 Work** | ⌘1 | 会话树、任务、任务树 | "我在干什么" |
| **变更 Changes** | ⌘2 | Git、Diff、代码审查 | "它改了什么" |
| **资产 Assets** | ⌘3 | 设计库、原型、编辑器 | "产出了什么" |
| **知识 Knowledge** | ⌘4 | 索引仪表盘、Memory、插件/MCP | "它知道什么" |
| **系统 System** | ⌘5 | Token 统计、进程、设置 | "代价与健康" |

动作类（新会话、命令面板、主题）移入顶栏与命令面板。rail 永不满溢，⌘1–5 直达，肌肉记忆可用。

### 3.2 检查器右栏：修好它，并让它成为灵魂

把审计中发现的断头右栏（P0-1）接通为**情境检查器（Inspector）**：340px 可拖宽，⌘I 开合。它不归属任何固定功能，而是**跟随当前焦点对象**——点消息里的文件卡片显示 diff，点权限请求显示风险明细，点设计产物显示预览，点 token 计显示用量拆解。"选中即检视"是 macOS 用户最熟悉的心智，也让主区永远不必被整页替换（设置改为浮层，见 3.5）。

### 3.3 控制不打断：权限队列化

把逐条弹出的权限问答改为**审批队列卡片**：一次 assistant 回合的所有待决项聚合为一张卡，每项是带风险色标的勾选行，支持"全部允许本轮 / 逐项决定 / 始终允许同类"。流不掐断——agent 继续做不依赖审批的部分，审批在检查器中也可并行处理。deny 决定以可见的"已拒绝"胶囊显示在队列里，取代隐晦的 `pendingPermissionReply` 合并。

### 3.4 指挥面板即一切：真模糊、全覆盖

命令面板升级为真正的核心入口：模糊匹配（fzf 风格评分），覆盖**所有**面板、主题、slash 命令、会话、文件、设置项、defineAction。快捷键表、slash 菜单、命令面板三份清单合并为同一注册表的三个视图，消灭"三个入口三种能力"的现状。

### 3.5 浮层归栈：一个 Esc 统治一切

所有模态/浮层（palette、undo、shortcuts、trust、diff、settings、preview）进入一个统一栈：Esc 永远关闭最上层，⌘. 全部关闭，背景点击只关最上层。设置从"整页替换主区"改为居中浮层，聊天流保持在背景可见——心流不中断。

## 4. 人体工程学基线

- **Fitts 定律**：发送键放大并固定在 composer 右下角；高频操作（停止、重试、审批）全部集中在 composer 一臂之内；rail 目标 ≥40px。
- **键盘全覆盖**：⌘1–5 切区、⌘I 检查器、⌘K 命令、⌘N 新会话、⌘. 专注模式（隐藏双栏只留消息列）、Esc 退栈、J/K 在阶段间跳转。
- **密度与字号**：三档密度（comfortable / default / compact）+ 界面字号独立缩放，取代写死的 13.5px。
- **可读性**：正文字号基准提到 14px，行高 1.6；辅助文字不低于 11.5px；全部主题过 WCAG AA 对比度（当前 line 主题的浅灰描边文字是重灾区）。
- **动效纪律**：`prefers-reduced-motion` 全局生效；脊柱动画只呼吸、不位移。
- **一致性**：emoji 图标全部替换为描边 SVG 体系；tooltip 统一为 data-tip 体系；i18n 硬编码清零。

## 5. 视觉方向：以 orca 主题为旗舰

现有 6 套主题架构（`ui.css` 结构 + `--ui-*` token 换肤）原样保留——这是竞品没有的能力。重设计以 **orca（赛博 HUD 深色）为旗舰主题**打磨默认体验：

- 深色为底、青蓝生物荧光为强调色（虎鲸意象：深海 + 声呐脉冲）。
- 阶段脊柱是当前阶段的"声呐脉冲"发光源，是视觉上唯一的高亮动态元素。
- 玻璃拟态只用于浮层层，工作区保持平面，避免视觉噪音。
- 其余 5 主题作为"皮肤平等公民"，新组件一律只消费 `--ui-*` token，禁止硬编码色值。

## 6. 落地路径（与审计报告的优先级对应）

| 阶段 | 内容 | 对应审计项 |
|---|---|---|
| **第一波：止损** | 修复右栏 grid 归属；rail 取消条件显隐；统一 Esc 栈；emoji→SVG | P0-1/2、P2-1/2/3 |
| **第二波：结构** | rail 收编 5 区 + ⌘1–5；检查器接通；权限队列；命令面板全覆盖；设置浮层化 | P1-1/2/3/4/5 |
| **第三波：差异化** | 阶段脊柱 + 阶段折叠摘要；任务树画布化（git-graph 视觉）；通知中心；onboarding 导览；密度/字号档位 | 愿景 §2–4 |

第三波是把 DeepOrca 从"又一个 AI 聊天客户端"里拉出来的关键——但也只有在第一、二波把结构理顺之后才值得做。
