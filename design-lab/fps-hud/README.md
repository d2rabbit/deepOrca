# DeepOrca · FPS HUD 座舱 — Agent UI 概念稿

> **design-lab 灵感稿，不属于产品源码。** 本目录只有这份文档和 `fps-hud.html`
> （零依赖，双击即可在浏览器打开），不影响也不引用任何 `packages/*` 代码。

## 一句话概念

**用户不是在"看一个聊天窗口"，而是坐进 agent 的座舱：**
中央是 agent 的视区（通讯流 + 工作面），一切系统状态按第一人称游戏 HUD 的
屏幕锚点环绕四周——左上目标、右上雷达、左下载具状态、右下武器系统、底中
指令台。信息有"方位感"：你不用读界面，你**扫一眼**就知道 agent 在哪、
在做什么、需要你按什么键。

## 为什么是第一人称

| 传统 agent UI 隐喻        | FPS HUD 隐喻                   | 带来的差异                     |
| ------------------------- | ------------------------------ | ------------------------------ |
| 列表 / 表单 / 面板        | 座舱仪表 / 锚点浮层            | 状态按方位固定，肌肉记忆可依赖 |
| 阅读聊天记录              | 监听通讯流（comm feed）        | 输出是"实时战况"，不是文档     |
| 点击按钮授权              | 互动提示：按 F 授权 / Esc 拒绝 | 键盘优先，打断感低、决策快     |
| 侧边栏选模型              | 换武器 / 换弹匣（512K MAG）    | 模型、思考深度、配额变成装备感 |
| 进度条                    | 罗盘步进 + 准星状态            | 回合内步骤可数，忙碌/空闲一眼判 |
| 错误 toast                | 屏幕边缘受击红闪               | 错误有方向、有冲击力，不丢     |

核心原则：**HUD 是状态层，不是装饰层。** 每个元素都绑定一个真实信号
（上下文用量、配额、工具事件、权限请求），没有纯装饰的仪表。

### 每个锚点 ↔ DeepOrca 真实功能映射

| HUD 锚点                 | 游戏原型           | DeepOrca 对应物                                       |
| ------------------------ | ------------------ | ----------------------------------------------------- |
| 顶部罗盘 COMPASS         | 任务步进/waypoint  | 当前回合的工具调用步数（Step i/N）                    |
| 左上目标 OBJECTIVES      | 主/支线任务        | PlanCard / 任务树（主目标 = 计划必做项）              |
| 右上雷达 RADAR           | 小地图             | 会话切换 + 面板入口（知识库 K / 源控 G / 设计 D / 任务树 T） |
| 右中作战流 FEED          | 击杀信息流         | ToolActivityPanel 的轻量化：工具事件逐条滑入、自动淡出 |
| 左下载具状态 VITALS      | 血量/护甲/能量     | ContextProgress（CTX + 压缩阈值刻度）、端点配额、花费  |
| 右下武器 WEAPON          | 弹药/武器轮        | TopBar 模型选择器 + 思考深度 + 联网开关 + 模式保险    |
| 底中指令台 CONSOLE       | 通讯/命令输入      | Composer（`▸` 提示符；PLAN/BUILD = 保险开关）         |
| 中央弹层 AUTH            | 互动提示 "按 F"    | PermissionCard：危险命令红色斜切框、键盘 F/Esc        |
| 边缘受击 EDGE FLASH      | 受伤方向指示       | 失败/被拒（FailureBanner、授权拒绝）从边缘红闪        |
| 准星 RETICLE             | 瞄准点             | agent 忙碌/空闲指示：流式输出时核心脉冲               |
| 开机自检 BOOT            | 进图加载           | 引擎启动序列（路由/记忆/供应商工具自检）              |

## 视觉语言

- **基底**：近黑 `#04070b` + 蓝图网格 + 暗角（vignette）。中央视区最亮、四周
  压暗——第一人称的"视野聚焦"。
- **信号色**（可整体换肤为不同"阵营色"）：
  - 战术薄荷 `#5df2c8` = 正常信号 / 成功 / agent 本体
  - 琥珀 `#ffb454` = 进行中 / 警告 / PLAN 模式 / 用户（指挥官）通道
  - 危险红 `#ff4655` = 权限请求 / 失败 / 受击
  - 链路蓝 `#59a7ff` = 副武器 / 快速通道 / 花费
- **字体**：遥测与正文用等宽（Cascadia/JetBrains Mono）；标签用窄体大写
  （Bahnschrift），`letter-spacing: 0.2em+`——HUD 标签的"军用铭牌"质感。
- **形状**：1px 细线框 + 角括号（四角两两成对）；唯一重武器级元素（授权弹层）
  才用斜切角（chamfer）双层描边。圆角 = 0，圆润与 HUD 语法冲突。
- **玻璃**：只允许 `backdrop-filter: blur(5px)` 级别的薄雾，不做毛玻璃卡片。

## 动效系统（状态驱动，而非装饰驱动）

| 状态         | 表现                                              |
| ------------ | ------------------------------------------------- |
| 空闲         | 准星慢速旋转，一切静止                             |
| 工作中       | 准星核心脉冲、罗盘当前步琥珀闪烁、FEED 逐条滑入    |
| 等待授权     | 中央弹层切入，`F` 键帽呼吸辉光                     |
| 失败 / 拒绝  | 屏幕边缘红闪一次 + FEED 红条 + 通讯流追加处理说明  |
| 开机         | BOOT 自检文字逐行打出后淡出（约 2s，可跳过）       |

**克制条款**：HUD 元素本身不做漂浮/发光循环动画（稳定 = 可读）；扫描线与网格
透明度压到 5% 以下；`prefers-reduced-motion` 下全部动效降级为瞬时态
（mockup 已实现：时间线直接跳到终态）。

**HUD 密度**（游戏惯例，落地时应做成三档）：
- `FULL`：全部锚点（本 mockup）
- `LITE`：只留 VITALS + AUTH + CONSOLE（日常写码档）
- `OFF`：只剩中央视区 + CONSOLE（沉浸阅读档）

## 交互语法

1. **键盘优先**：授权 `F` / `Esc`；模式 `Tab`；指令面板 `Ctrl+K`；面板热键
   `K/G/D/T`（雷达下方模块条）。鼠标仍是完整兜底。
2. **授权三态**：单次授权 / 本会话记住（现设置项）/ 拒绝（触发边缘红闪并让
   agent 口头确认"已跳过，改动保留在本地"——拒绝也要有反馈闭环）。
3. **中央视区神圣不可遮挡**：所有 HUD 锚点都在两侧留白区；唯一中央弹层是
   AUTH，且它出现在视区下沿与指令台之间，不盖正文。窄屏（<1280px）自动
   藏 FEED、缩放侧锚点。

## 若未来落地（路径备忘，本次不做）

本仓库的主题体系是**令牌层**（`styles-*.css` 只绑 `--ui-*`），布局归
`ui.css` / `ui-css/shell.css` 所有。FPS HUD 改的不只是皮，而是 **shell 布局**，
所以它不该是"第 7 套主题"，而是一个成对交付物：

1. `App.tsx` 增加 `data-shell="fps"` 布局模式（与主题正交，任何主题色都可配）。
2. 新增 `ui-css/shell-fps.css`（锚点定位骨架）+ `styles-hud.css`（信号色令牌）。
3. 新增少量 HUD 专用组件：`Gauge`（分段刻度条 + 阈值 mark）、`FeedTicker`、
   `Radar`、`Reticle`、`AuthPrompt`（PermissionCard 的 HUD 皮肤复用同一数据流）。
4. i18n：所有铭牌文案走 `messages.ts`（本 mockup 中的中英混排仅为效果演示）。
5. 风险清单：长文阅读密度（HUD 挤占横向空间 → 密度档位兜底）、CJK 宽字距标签
   的换行、暗色-only（需定义浅色"沙漠涂装"或明确仅暗色）、动效晕动症
   （reduced-motion 必须全程尊重）。

## Mockup 使用说明

- 直接双击 `fps-hud.html`（或拖进任意浏览器）。建议窗口 ≥1280px 宽。
- 演示时间线约 10 秒：read → write → npm test → 目标勾选 → 通讯流打字 →
  弹出授权请求。
- 可交互：`F` 授权 / `Esc` 拒绝（拒绝会触发边缘红闪 + agent 跟进说明）；
  右下"⚡ 重播授权演示"；标题栏 `↻ REBOOT` 重播开机；PLAN/BUILD 可切换；
  指令输入框可聚焦。
- 所有数据（模型名、测试数、百分比）均为演示值。
- 提示：若浏览器窗口处于后台/被遮挡，Chromium 会节流定时器与动画，
  开机自检和打字机演示会变慢、入场动画可能停在中间帧——切回前台即恢复正常。
