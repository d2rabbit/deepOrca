## 0. 一句话

把主会话区固化为**三栏**：左侧「指令目录」、中间「会话流（去气泡 + 行为流缩略行 + 计划卡）」、
右侧「常驻活动区（思考瞬态卡 + 画中画活动堆叠 + 子代理组）」；输入框泊定中列底部与中列同宽；
右侧浮动 Tab（审查报告等快速视图，项目内既有形态）出现时**活动区整体收缩为细条**，关闭即恢复。
所有图标一律 SVG；两列容器本身**不带边框底色**，只有内容元素有面。

## 1. 目标布局（与 demo-flow.html 一致）

```
┌────────────────────────────────────────────────────────────┐
│ mockbar（演示控件；落地后为应用顶栏）                        │
├──────────┬──────────────────────────────┬──────────────────┤
│ 指令目录  │  会话列（.chatcol）           │ 活动区列(.actcol) │
│ (.toc)   │  ┌────────────────────────┐  │ width 316px      │
│ 208px    │  │ .scroll（唯一滚动层）    │  │ ├ 思考瞬态卡(动态)│
│ 常驻     │  │  sysnote / user-card   │  │ ├ 实时活动流      │
│ 无框     │  │  ai-row(名牌+行为流+md) │  │ │ (画中画堆叠)    │
│          │  │  plancard / perm       │  │ └ 子代理组(靠底)  │
│          │  └────────────────────────┘  │   窄屏→胶囊下拉   │
│          │  .composer（泊定，同宽对齐）   │  浮动Tab→收缩细条 │
└──────────┴──────────────────────────────┴──────────────────┘
```

### 布局不变量（滚动契约，沿用 task-tree-hub §6.5）

- 三栏均为 **flex 列**，逐级 `min-height: 0`；**唯一滚动层** = 会话列 `.scroll`。
- 活动区列是**实体列**（非悬浮）：宽 316px、无边框无底色（隐形容器），内部元素自带面。
- 浮动 Tab（`.float-tab`）出现 → `body.tab-open` → 活动列收缩为 40px 细条（仅竖排标签 +
  计数），会话列不被遮挡（浮动 Tab 悬浮于会话列右缘之上，属项目既有交互形态）；关闭恢复。
- 输入框：`.chatcol` 内 `flex: none`，与中列同宽对齐；不随内容滚动。
- 窄窗（< 900px）：目录隐藏、活动列收缩为细条、画中画堆叠隐藏、浮动 Tab 宽度
  `min(440px, 62%)`。

## 3. 关键设计决策（实现时必须遵守）

### 3.1 三栏均为隐形容器

`.toc` 与 `.actcol` **不带边框与底色**，只有其内部元素（目录项、胶囊、画中画小窗、清单）拥有
表面。列与列之间用 `gap: 12px` 分隔，不用分割线。

### 3.2 引用芯片 = 行内原子芯片

- 尺寸公式：`height: 1.28em; vertical-align: -0.17em; font-size: 0.9em;`（锁定行高比例，
  光学居中，随文字换行永不错位）。
- 五类独立标识（demo 与落地方案同一张色表）：

  | 类型 | 色值 | 图标 |
  | ---- | ---- | ---- |
  | 文件 | `#5f6b7a` 石墨 | `i-doc` |
  | wiki | `--ui-accent` 蓝 | `i-book` |
  | 技能 | `#9a36b8` 紫 | `i-spark` |
  | 命令 | `#e8590c` 橙 | `i-terminal` |
  | 审查报告 | `#2f9e44` 绿 | `i-shield` |

- Composer 内实现 = **遮盖层 + 浮动标签**（已定稿）：镜像层携带与 textarea 逐字符相同的
  原始 token（透明墨水、不透明卡色填充遮盖真实路径），缩略芯片绝对定位在 token 起点；
  芯片是原子整体，光标进入只亮 accent 描边，路径永不出露。

### 3.3 活动区数据流（复用既有通路，不改 core）

- **工具活动事件**：复用 `ToolActivityPanel` 已订阅的实时 tool-activity 流
  （`buildToolSummary` 同源）；ActivityRail 维护 `activity-store`：`spawn → running → done/err`、
  按时间排序、**15 封顶**（超出挤出最旧）。
- **会话流缩略行**：历史消息渲染仍走 `SessionMessage`（持久化通路不变）；活动区只消费
  **实时事件**。两者天然一致——同一事件既落转写（缩略行）也进活动区（小窗）。
- **子代理**：agent 事件中 `nested` 层（TaskRecordPanel trace 同源）单独进「子代理」组；
  子代理窗体点击下拉展开它自己的活动清单。
- **思考**：thinking 消息驱动瞬态卡（实时字数/计时）；完成即散，流内留缩略行。**不进堆叠**。

### 3.4 画中画窗规格

- 窗体：240×292（四四方方），顶缘 3px **类型色**条 + 标题栏同色 8% 淡染 + 图标同色；
  内容区完整呈现内部操作（输出/差异/JSON 原样），超长**窗内滚动**，不裁剪不省略。
- 堆叠：同屏 4 扇（240×292，阶梯步进 top+34/left+20，不透明度 1→0.9→0.72→0.5），
  **最新恒在最前最上**；点击任意窗提到最前；「+N」展开全部 15 条清单（点行置前）。
- 类型色表：bash `#e8590c` · read `#1c6fe0` · edit `#d6386c` · grep `#0ca678` ·
  mcp `#1098ad` · skill `#9a36b8` · doc `#5f6b7a`。

### 3.5 计划卡双态

- **提案态**：`<proposed_plan>` 按标题/编号解析为段（fallback：整计划单段）；头部 =
  📋 图标 + 琥珀「待审批」徽章 + 「N 段 · M 步」；段可折叠；底部「继续打磨 / 开始实施」。
- **执行态**：批准后原地转执行态——蓝「执行中 · 段 N」徽章 + accent 描边 + 头部进度条；
  段三态（已完成打勾划线 / 进行中蓝左缘高亮 + 当前步骤 / 待开始折叠）；**同时钉住会话顶**
  一条紧凑进度条（段点 + 进度 + N/M 步），点击展开回完整卡；进度由 UpdatePlan 工具驱动
  （既有通路）。

### 3.6 状态语义（沿用定稿）

- 思考/工具/技能/MCP/bash/文件修改的**具体信息一律进画中画/展开区**，会话流只留缩略行。
- `statusNote`（模型可读英文诊断）**永不直接渲染**；UI 按 `meta.status`
  （active 无提示 / degraded 琥珀条 / unavailable 灰条）本地化展示（已落地，保留）。
- 关闭/箭头/对勾等排版字符保留为文本；**彩色 emoji 图标一律 SVG**（ui/icons.tsx 既有 55 +
  本方案新增 6）。

## 4. Message.tsx 拆分方案（会话流重构的文件级动作）

现状：单文件 900+ 行承载全部消息类型。拆为：

| 新文件 | 职责 | 迁出内容 |
| ------ | ---- | -------- |
| `components/message/UserMessage.tsx` | 用户卡（技能附件 + 引用芯片 + 图片） | Message.tsx user 分支 |
| `components/message/AssistantMessage.tsx` | 名牌 + markdown + 流式状态行 | assistant 分支 |
| `components/message/ThinkingRow.tsx` | 思考缩略行 | thinking 块 |
| `components/message/FlowEventRow.tsx` | 工具/MCP/bash 缩略行 | tool 分支的 ui-tool-card |
| `components/message/SystemNote.tsx` | 技能载入/系统提示 | system 分支 |
| `components/message/ReferenceSegments.tsx` | 引用芯片渲染（正文侧） | 既有 ReferenceSegments |

`Message.tsx` 保留为类型分发壳（≤200 行）。`chat.css` 对应段落迁移，选择器不变的部分
（`.ui-bubble*` 等）随迁移清理。

## 5. 活动区（ActivityRail）实现要点

### 5.1 store（`lib/activity-store.ts`，新建）

- 状态：`windows: PipWindow[]`（≤15，`{ id, kind, title, phase: running|done|err, body, startedAt, durationMs }`）、
  `think: { active, chars, seconds, summary } | null`、`subagents: Subagent[]`。
- 事件接入点：ToolActivityPanel 现用通路（transcript 工具事件）+ 会话流工具消息；每事件
  upsert 一扇窗。15 封顶 FIFO 挤出。

### 5.2 视图

- 前窗（最新）完整呈现；旧窗阶梯退后（步进 top+34 / left+20，透明度 1→0.5）。
- 点击窗体提到最前；「+N」展开 15 条清单（点行置前）。
- 浮动 Tab（TaskQuickSheet / 报告快速视图）打开 → `body.tab-open` → 活动列收缩 40px 细条；
  关闭恢复。窄窗自动收缩。

### 5.3 子代理组

- 组头胶囊「子代理 · N」（常驻，N=0 时整组隐藏）；窄/收起态 = 胶囊下拉清单。
- 子代理窗：左缘 3px 子代理紫、名称 + 实时步骤滚动；点击下拉完整活动。

## 7. 测试与验收

- **DOM 断言**（沿用 `run-tests.mjs` + dom-harness 模式）：
  - composer：镜像层 = 遮盖层携带原始 token、芯片不含路径、编辑态类翻转（既有 6 例扩展）。

## 9. 风险与对策

| 风险 | 对策 |
| ---- | ---- |
| 主题（12+ 套）下类型色对比不足 | 类型色走 `--kc` token + `color-mix` 淡染，暗色主题已验证；上线前逐主题截图走查 |
| CJK IME 与芯片编辑冲突 | 芯片为纯表现层（textarea 值不变），IME/undo/发送通路零改动；沿用既有 IME 守卫 |
| 长会话性能（15 扇画中画窗常驻 DOM） | 窗体内容惰性渲染（非前窗只保留标题 + 摘要）；store 层对事件做节流合帧 |
| 旧会话回放含历史 thinking/tool | 缩略行渲染与实时事件同一组件，历史无运行态即静态展示，天然兼容 |
| `statusNote` 旧报告无结构化 status | 兜底：无 `status` 字段的旧报告按 active 处理（不显示状态条），不做字符串解析 |
