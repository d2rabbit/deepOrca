# 多窗口与真助理 · 全域任务（multi-window-assistant）— 任务清单

> 对应设计：[design.md](./design.md)。2026-09-14 立稿，概念/方案稿（未开工）。
> 上游纲领：[docs/features/next-next-version-plan.md](../../../docs/features/next-next-version-plan.md) §2（域）/§3。
> 红线：助理不新造能力体系（调用既有 action，仍走 tier + `sideEffects` 网关）；能力执行**绑定发起域**（不读当前活跃 root）；系统面唤起**默认保守 + 默认关**；不做"助理即新聊天机器人"（是编排层）；重资源（embedding/memory 服务）进程级共享不 per-domain 复制；依赖支柱一 + 支柱二。

## N3.1 多活工作域

- [ ] **N3.1.1** per-root 引擎实例：`DomainInstance`（root/bridge/registry/state），取代 `index.ts:593-614` 模块级单例
- [ ] **N3.1.2** 三态生命周期：`active` / `warm`（引擎在 + 事件流在 + UI 未挂载）/ `frozen`（复用 PiP 快照语义 `App.tsx:1000-1034`），支持 frozen → warm/active 晋升
- [ ] **N3.1.3** 资源治理：活跃域上限（默认 3–4，对齐 PiP 上限）+ 超出按最后交互时间降级 + **显式提示**（不静默杀域）
- [ ] **N3.1.4** 重资源保持共享：memory / embedding 服务进程级单例不 per-root 复制（只隔离数据与索引）
- [ ] **N3.1.5** 测试：双域并行互不干扰；切域不重置另一域；上限触发降级路径；frozen 晋升

## N3.2 事件流按域路由

- [ ] **N3.2.1** 事件携带域标识 + `emitTo({ domain }, channel, payload)`（与支柱二窗口订阅模型**同一机制**，不重复实现）
- [ ] **N3.2.2** 能力执行绑定发起域 root（消灭"切走工作区导致后台任务用错 root"）——`ActionRegistry` 构造期 root 语义扩展到全域
- [ ] **N3.2.3** `action-ipc.ts` 既有目标 root 打戳不变式从进度事件扩展到全域事件
- [ ] **N3.2.4** 验收：后台域流式输出**实时可见**（消灭 `App.tsx:997-999` 的 snapshot by design）；跨域并发各用对 root 回归测试
- [ ] **N3.2.5** 事件节流：按域批量节流（复用既有进度节流先例），warm 域只汇流不挂完整 UI

## N3.3 真助理唤起路径（依赖支柱一 P4）

- [ ] **N3.3.1** 域内事件 → 助理判定是否打断（**默认保守**：仅"需人决策"与"长任务完成"两类；阈值用户可调）
- [ ] **N3.3.2** 系统面投递：Notification（点击 → 路由到该域窗口/槽位）/ Tray 徽标计数 / 全局快捷键直接唤起
- [ ] **N3.3.3** 平台不支持时**诚实降级**（窗口面 → 界面面）并在能力清单 UI 标注
- [ ] **N3.3.4** 测试：默认关时零打扰；通知点击到达正确域；降级路径呈现
