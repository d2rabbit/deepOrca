# 多窗口与真助理 · 全域任务（multi-window-assistant）· 技术设计

> **状态**：**概念/方案稿（只出方案，不改代码）** · **日期**：2026-09-14 · 分支 `feat/modern-ui-redesign` · **next-next 规划区支柱三**。
> **上游纲领**：[`docs/features/next-next-version-plan.md`](../../../docs/features/next-next-version-plan.md)（§2 域 · §3 依赖图 · §6 红线）。
> **用户定调**：**以多窗口和真助理的方式实现全域任务设计。**本 spec 是该定调的落地：多窗口是形态，域是边界，真助理是**跨域的编排者**。
> **对应实现域**：`packages/desktop/src/main/`（多活工作区实例 + 事件流路由 + 助理编排）+ `packages/desktop/src/renderer/`（多域 UI）+ `packages/core/src/`（编排能力的复用，非新增）。**依赖支柱一 + 支柱二**。

---

## §0 执行摘要

当前是**单活跃引擎实例**：一个 `projectRoot` state、一个 `SessionBridge` 全局单例（`index.ts:593-614`）、一个 `ActionRegistry`；切换工作区触发**全局重置**（`App.tsx:1046,1062`）。所谓"多工作区"只有两处 UI 便利——侧栏树的只读枚举，以及 **PiP 冻结快照**（`App.tsx:997-1039`），后者自陈其局限：

> *"Background roots get no message/entry streams here, so the preview is a snapshot by design"*（`App.tsx:997-999`）

**即：后台域不接收事件流。** 这是"全域任务"的第一硬阻塞。第二个硬阻塞是 OS 集成面为零——没有托盘/全局快捷键/通知，助理只能在你已聚焦主窗口时工作。

本 spec 做三件事：**① 多活工作域（per-root 引擎实例 + 事件流按 root 路由）② 真助理（跨域编排者，需要时唤起你）③ 全域任务面（跨域任务视图与移交）**。

## §1 多活工作域

### 1.1 per-root 引擎实例

现状：`bridge` / `pluginManager` / `memoryManager` 全是模块级单例（`index.ts:593-614`），`getBridge()` 惰性单例（`:670-675`）。

目标：**域 = 引擎实例的作用域**（纲领 §2）：

```ts
interface DomainInstance {
  readonly root: string;                  // 工作域标识（工作区根）
  readonly bridge: SessionBridge;         // per-root 引擎
  readonly registry: ActionRegistry;      // per-root 能力注册表
  readonly state: "active" | "warm" | "frozen";
  // 资源：会话管理器 / 记忆 / 索引 / 任务树 均随域独立
}
```

- **`active`**：全量运行（事件流实时推送、LLM 循环可用）；
- **`warm`**：引擎在、事件流在（后台推进）、UI 未挂载——**这是"全域任务"的关键新态**（今天不存在：后台 root 无事件流）；
- **`frozen`**：降级快照（复用现有 PiP 语义，`App.tsx:1000-1034`），可一键晋升为 warm/active。

**资源治理**：活跃域上限（默认 3–4，与 PiP 的 4 个上限一致）+ 超出时按"最后交互时间"降级为 frozen + 显式提示（不静默杀域）。

### 1.2 事件流按域路由

现状 `emit()` 全窗口广播 + `emitToMain()` 定向，**没有域维度**。目标：事件携带域标识，UI 按域订阅（与支柱二的窗口订阅模型**同一机制**）：

```ts
emitTo({ domain: root }, channel, payload);   // 域内所有挂载视图订阅
```

- 后台域的推进（会话流式输出、action 进度、任务状态变化）**实时可见**——这是消灭"snapshot by design"的那一步。
- 主进程侧的进度事件已由 `action-ipc.ts` 用**目标 root** 打戳（AGENTS.md 记载的 `getRoot(id, input)` 不变式），本 spec 把这条既有不变式从"进度事件"扩展到**全域事件**。

### 1.3 跨域一致性

- **能力调用的域归属**：能力执行时绑定发起域的 root（复用 `RegistryHost.projectRoot`），不依赖"当前活跃工作区"——消灭"切走工作区导致后台任务用错 root"这一类缺陷。
- **共享资源**：memory / embedding 服务是进程级单例（`closeEmbeddingService()` 宿主管理，AGENTS.md 有载）——**保持共享**，不 per-root 复制模型句柄；域只隔离数据与索引，不隔离重资源。

## §2 真助理（跨域编排者）

### 2.1 助理的双重身份

"真助理"不是一个新的聊天窗，而是**域之上的编排层**：

| 身份 | 含义 | 复用 |
| --- | --- | --- |
| **协调者** | 跨域发起任务、观察进度、必要时移交 | `ActionRegistry` 的编排能力 + `runSubagent` / `runBackgroundTask` 既有 seam |
| **唤起者** | 在你不看屏幕时通知你（系统面） | 支柱一 P4 的 Notification / Tray / globalShortcut |

**关键约束**：助理**不新造能力体系**——它调用的是既有 ~40 action（P1 数据面）；它新增的是**跨域视角**与**系统唤起**。红线：助理的每次跨域调用仍走 tier + `sideEffects` 权限网关（纲领红线 4）。

### 2.2 唤起路径（依赖支柱一 P4）

```
域内事件（任务完成 / 需人工确认 / 失败）
   → 助理判定是否需要打断人（阈值与静默策略，默认保守）
   → 系统面投递：Notification（点击 → 路由到该域的窗口/槽位）
             或 Tray 徽标（红点/计数）
             或 全局快捷键直接唤起（无需先找主窗口）
```

- **默认保守**：只有"需要人决策"与"长任务完成"两类触发通知；域内进度**不**打断人（在域视图内看）。
- **不静默失效**：平台不支持某系统面时降级到下一可用平面（窗口面 → 界面面），并在能力清单 UI 如实标注（纲领红线 7）。

### 2.3 全域任务面

多域并行后的**人机界面**（这是"全域任务设计"的字面落点）：

| 面 | 内容 |
| --- | --- |
| **全域任务总览** | 跨域的运行中任务/会话/action 单表（域列 + 状态 + 进度），复用既有进度事件与任务树 |
| **域切换与并行视图** | 域列表 + 各域状态（active/warm/frozen）；PiP 从"冻结快照"升级为"活的域缩略"（warm 域有事件流） |
| **跨域移交** | 把任务/上下文从一个域移交到另一个域（复用任务树的 branch/fork 语义 + 会话 taskRef 绑定） |
| **助理会话** | 一个**跨域**的编排会话（不绑定单域），其任务是分发与汇总（复用 `runSubagent` 的 `silent` 语义做静默分派） |

## §3 分期

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| **N3.1** | 多活工作域：per-root 引擎实例 + `active/warm/frozen` 三态 + 资源上限与降级 | 开两个域并行推进，后台域**事件流实时可见**（不再是快照）；切域不重置另一域；上限触发降级并提示 |
| **N3.2** | 事件流按域路由（与支柱二订阅模型同一机制）+ 能力执行域归属（消灭"用错 root"） | 后台域流式输出可见；跨域并发执行各自用对 root（回归测试） |
| **N3.3** | 真助理唤起路径（依赖支柱一 P4）：通知/Tray/快捷键 → 路由到域 | 长任务完成可系统通知（默认关时无打扰）；点击通知到达正确域窗口；平台不支持时诚实降级 |
| **N3.4** | 全域任务面：总览表 + 域并行视图 + 跨域移交 + 助理会话 | 全域任务单表可见且可跳转；跨域移交可用；助理会话能跨域分派并汇总 |

## §4 风险与对策

| 风险 | 对策 |
| --- | --- |
| 多实例资源爆炸（N 份记忆/索引/会话） | 重资源（embedding/memory 服务）进程级共享；域只隔离数据面；活跃域上限 + 降级 + 用户可见 |
| 域切换导致后台任务用错 root | 能力执行**绑定发起域**（不读"当前活跃 root"）；`action-ipc.ts` 既有目标 root 不变式扩展到全域事件 |
| 通知滥用打断人 | 默认保守（仅"需人决策"与"长任务完成"）；全部系统面默认关；打断阈值用户可调 |
| warm 域事件流与渲染性能 | 域视图懒挂载（warm 域只跑事件汇流，不挂完整 UI）；事件按域批量节流（复用既有进度节流先例） |
| 跨域移交的上下文一致性 | 移交走任务树 branch/fork + 会话 taskRef 绑定（既有语义），不新造上下文搬运格式 |
| 与 module-system / 远程访问重叠 | 域生命周期属本 spec；模块动态化归 B1；远程会话属主线 C——**三方共用"域"概念但不共享 spec**，接口在落地时对表 |

## §5 明确不做

不做域网/跨设备（归支柱四）；不做窗口宿主与 surface 装载（归支柱二）；不做能力清册与 OS 面注册机制（归支柱一，本 spec 只**消费**其系统面）；不做模块系统与发行版（归 module-system）；不新造权限模型；不做移动端；不做"助理即新聊天机器人"（助理是编排层，不是第四种会话类型）；不改主窗口单例地位。
