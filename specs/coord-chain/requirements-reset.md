# 工作链 · 需求基线（重新梳理版）

> 2026-09-07 · 依据：仅本轮对话中你亲自给出的表述。**不继承**任何旧方案（v1–v7 设计稿已删除；旧 spec / OC 计划 / 旧 R 编号一律不作为本文依据）。
> 用途：进入设计前对齐的共同事实基线。每条需求都有出处（你的原话要点），不确定项标注【待确认】。

## 1. 一句话定位

**工作链 = 任务链。** 它不是新面板、不是新视图，而是把"链"作为**隐藏基础设施**，长在**现有产品的任务树**上；任务树是整条链**唯一共享**的东西。

## 2. 三条铁律（设计的硬约束）

| # | 铁律 | 你的原话要点 |
| --- | --- | --- |
| 铁 1 | **链路隐藏** | "链路本身是隐藏行为，对外是在任务树上操作"——账本/组网/加密等不产生界面 |
| 铁 2 | **任务树唯一共享** | "任务树是全链唯一共享"，其他一切在各对应模块本地做版本管理 |
| 铁 3 | **基于现有产品** | "在现有的基础上设计，不要增加其他多余的设计"；"UI 必须和项目本体的一模一样" |

由此推出【明确不做】：不新增独立工作链面板/视图；不新增会话区域（主会话区保持原样）；不新增引导卡/演示面板/装饰性组件；链状态条、封存动效、引导流程等一律不做。

## 3. 实体模型

- **工作区（= 任务区 = 会话模块的分组）**：会话模块里的每个分组就是一个工作区；每个工作区有**独立的工作区编号**，并**自动生成唯一的任务链 ID**（"每个任务区都有一个独立的链 id"）。
- **任务树**：本身参考 git 设计（fork / merge / 分支），**与分支联动**；树上节点 = 任务。
- **域**（工作区不只包含主会话）：💬 主会话（chat）、✏️ 编辑器（chat 任务的变种）、🎨 设计（原型设计 + 视觉稿设计）、📋 审查报告、📚 知识库。
- **链（隐藏层）**：每个任务区一条链；**fork 的任务链必须协同来源链**（记录来源链 / 来源工作区 / 来源分支）。

## 4. 行为需求

### B1 任务区身份
每个工作区（任务区）自动生成：独立工作区编号 + 唯一任务链 ID。展示必须最小化（如会话分组头一行小字），不得为此新增面板。

### B2 树上 fork（声明式）
"fork 其他人的分支任务，可以用任务树直接 fork"——在任务树节点上直接声明；来源链 / 来源工作区 / 来源分支**自动携带**，无需手工填写；fork 产生自动记录。

### B3 fork 落地规则（核心域规则）
| 域 | fork 行为 | 落地位置 | 会话任务 |
| --- | --- | --- | --- |
| 💬 主会话（chat） | fork 他人分支任务 | **本地落地为真实任务区**（会话模块新分组）+ 基线会话（对应代码检出到本地） | ✅ 生成 |
| ✏️ 编辑器 | chat 任务的变种；fork = "把别人的代码合并到你本地"（合入本地 worktree） | 会话模块（同 chat 路径） | ✅ 生成 |
| 🎨 设计（原型/视觉稿） | **可独立 fork**，不牵动主会话代码 | **设计模块内做版本管理**（产物/对应文件 fork 到本地） | ❌ 不生成 |
| 📋 审查报告 / 📚 知识库 | **与代码强绑定**：fork 时随代码整体 fork（代码 + 对应审查报告/知识库内容一起到你本地）；**不可独立 fork** | 审查 / 知识库模块内跟随版本 | ❌ 不生成 |

通用规则：**除 chat（含编辑器变种）外，任何 fork 都不生成会话任务**；所有 fork 的对应代码/产物都会 fork 到你本地，并且**必须做好版本管理**。

### B4 版本管理
fork 的内容都有版本：代码版本、设计稿版本（如 .ddp/.ddu v1→v2）、审查/知识库快照版本——在**各自对应模块**内可见、可管理。

### B5 合并
任务树上 cherry-pick 语义；merge 双亲上链（谱系回边）；**冲突只报告、不自动解决**（沿用现有任务树语义，编辑器中解决）；合并后源分支标注"已并入"并回写分支状态。

### B6 行为轨迹
整条任务链的**操作流程级**轨迹：谁做了什么、到哪里了、是否合并。**不是** agent 工具轨迹（不含工具调用记录）。承载位置：任务树内的子视图（不另建面板）。

### B7 分支联动
任务树的 fork / merge 与 git 分支联动：fork → 落 worktree 分支 / 检出；merge → 分支状态回写（已并入）。

## 5. 约束与呈现

## 7. 进入设计前需要你拍板的问题

1. **协作范围**：链是否仍以"局域网多设备同主题同链"为目标？还是本期先做**单机多任务区的链式谱系**（隐藏层只留身份+记录，不做组网）？——这决定隐藏层的规模。
2. **fork 声明是否上链**（不可篡改记录），还是仅本地记录？
3. **行为轨迹数据源**：链上记录聚合，还是本地 reflog 聚合即可？
4. **链 ID / 工作区编号的展示位置**：会话分组头一行小字？还是只在 fork 声明/轨迹中出现？
5. **设计 fork 是否也要树上声明**（含来源断言）？——设计不生成会话，但按"树上操作"原则疑似仍要声明。
6. **审查/知识库"随代码"的最小呈现**：树上锚行，还是只在 fork 声明文案里说明？
7. **设置段**：本期是否需要用户级开关/设备名/配额？
