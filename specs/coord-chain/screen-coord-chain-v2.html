读法：树节点 = 任务树分支（TaskTreeService）；节点上的标签 = 链上状态 （谁在用、是否已并入、fork 自谁）。Fork 别人的分支 = 在树节点上直接 fork（下一步）。 合并 = 树上 merge（cherry-pick 语义）+ merge commit 双亲上链 + 谱系回边。 审查报告 / 知识库没有独立分支——它们永远跟随 main（代码强绑定）。 视觉稿 design/passkey-ui 可以独立分叉（不牵动主会话）。

Fork 对面的分支 = 任务树上直接操作

TaskTree 本来就是 git 式设计：fork = 开分支、merge = cherry-pick、reflog = 操作日志。 跨工作区 fork 只多两件事：① 声明来源（哪条链/哪个工作区/哪个分支）； ② 把对面的 ws.commit 检出到你的本地（代码合入，编辑器/chat 变种同路径）。

不需要独立面板——任务树节点上直接操作；不需要复杂弹层——一行声明 + 自动对齐。

链上自动产生的记录（无需手工填写）：
task.claim → 声明性软锁（A 面板可见，不阻塞）
task.share → parentRecordId → 来源记录（谱系 ⑂ 边）
ws.checkout → 对面的 ws.commit 检出到本地
member/join → 跨链 fork 时新工作区入链
